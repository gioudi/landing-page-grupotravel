# SPEC: FIX-014 — Internationalization (ES / EN / DE) + Language Switcher

**Status:** Approved → Implemented
**Author:** Son of Ivaldi
**Date:** 2026-08-27
**Branch:** `feature/i18n`

---

## Problem

The landing page is hardcoded to **Spanish only**. All visible text lives directly in `index.html` and several sections still contain **Lorem ipsum** placeholder copy (About ×3, Packages), so the page reads as an unfinished demo rather than a real travel-agency site. There is also no way for a visitor to switch languages. FR requirements call for engaging, real copy; the current page does not provide it for monolingual users beyond Spanish.

Additionally, the **TTS player** (`src/ts/tts-player.ts`) is hardcoded to `lang = 'es-CO'` with Spanish-only voice preference and Spanish status strings (`'Leyendo en voz alta.'`, etc.), so even if text were translated, speech would not follow.

---

## Why

- **Mandatory:** the client wants i18n adoption with **Spanish, English, and Deutsch** and a way to switch between them. This is the primary incoming requirement.
- **Real content:** replacing Lorem ipsum with genuine travel copy in 3 languages makes the page credible and conversion-ready (a travel agency selling trips to multiple cities/countries).
- **TTS must follow the language** or bilingual/broken speech results; aligning TTS with the active locale is required for correctness and accessibility.
- **SEO:** updates to `<html lang>`, `title`, meta description, and Open Graph per language improve search relevance for the visitor's locale.

---

## Solution

Zero-dependency **runtime dictionary** i18n (fits the stack: vanilla TS, Vite, no frameworks, does not add to the bundle beyond a small module).

### New module: `src/ts/i18n.ts`
- `type Locale = 'es' | 'en' | 'de'`.
- `translations: Record<Locale, Translation>` — a dictionary keyed by stable `i18nKey`, with `text` (default content) plus optional `attrs` for `aria-label`, `placeholder`, `title`, `alt`.
- `getLocale(): Locale` — resolves persisted `localStorage('lang')`, else `<html lang>`, else `navigator.language` prefix, else `'es'`.
- `setLanguage(locale: Locale): void` — applies all `data-i18n` text and `data-i18n-attr` attributes, sets `document.documentElement.lang`, updates `document.title`, meta `description`, Open Graph (`og:title`, `og:description`, `og:locale`), Twitter title/description, and `hreflang` handling; persists to `localStorage`.
- `initI18n(): void` — wires the switcher buttons and calls the initial render.
- Exposes a small event so `tts-player` can re-sync voice/status on locale change.

### HTML wiring
- All hardcoded text in `index.html` (hero, about, packages, contact labels/placeholders/button, skip-link, footer, TTS labels/aria) becomes `data-i18n="key"` (with `data-i18n-attr="aria-label|placeholder|title|alt"` where needed).
- `<html lang="es">` initial; `<title>`/meta default in Spanish; runtime updates override for other locales.

### Location switcher (nav)
- Segmented control `ES | EN | DE` with `aria-pressed` per button, `aria-label` localized; keyboard accessible (buttons). Placed in `.main-nav`.

### Localized TTS (`src/ts/tts-player.ts`)
- Derive `lang` from active locale (`es-CO` for `es`; `en-US` for `en`; `de-DE` for `de`).
- Voice preference list per locale.
- Status strings (`'Leyendo en voz alta.'`, `'Lectura pausada.'`, `'Lectura detenida.'`) pulled from the dictionary.
- On language switch, stop any active speech and re-render status strings.

### Real copy (all 3 languages)
Write genuine travel-agency copy replacing every hardcoded string and Lorem ipsum: hero headline/subtitle, about (3 paragraphs), packages intro + CTA, contact labels/placeholders/button/success message, skip-link, footer note, nav labels, TTS labels. Content reflects a travel company that offers trips/packages to various cities and countries.

### SEO
- Set `hreflang` alternates (es/en/de) on the landing page (added during FIX-016 for the new pages).
- `og:locale` and canonical stay per configuration.

---

## Design Pattern Used

**Strategy** — locale selection via a pluggable dictionary; **Observer** — i18n module notifies the TTS player of locale changes; **Module** — each concern isolated in its own TS file.

---

## POO / SOLID / DRY

| Principle | Application |
|---|---|
| **S**ingle Responsibility | `i18n.ts` owns all translation/locale logic; `tts-player.ts` consumes a localized dictionary. |
| **O**pen/Closed | Adding a language = add one entry to the dictionary, no logic change. |
| **D**ependency Inversion | TS modules depend on a `Locale`/dictionary interface, not hardcoded strings. |
| **D**RY | One dictionary + one render function; no repeated hardcoded strings. |

---

## CSS Architecture

No structural ITCSS change. Switcher styling added to the nav components. Light/dark token usage for the switcher is completed in FIX-015 (do not mix specs).

---

## SEO Impact

Per-language `<html lang>`, title, meta description, OG tags, and hreflang improve targeted-search relevance. Caveat: because this is client-side runtime i18n, crawlers index the default (`es`) content only; localized *separate* pages for full per-language SEO are future work (see FIX-016).

---

## Performance Impact

Adds one small JS module (dictionary for 3 languages, ~2–4KB minified). Negligible. No network requests. Replaces duplicate Lorem ipsum text with real content.

---

## Security

- No `innerHTML`; all rendering uses `textContent` and attribute assignment.
- `localStorage('lang')` values validated against the allowed locale set.

---

## What We Avoid

1. Adding an i18n framework/dependency (unnecessary for this page).
2. Leaving Lorem ipsum / demo copy on a production landing page.
3. TTS reading in a language different from the displayed text.
4. Mixing the theme (FIX-015) or new pages (FIX-016) into this spec.
